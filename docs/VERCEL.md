# Deploy the hosted demo on Vercel

This branch supports a separately provisioned Neon Postgres database. The local Windows launcher still uses SQLite. The hosted database starts with fictional data and does not import your laptop's records.

1. Create a dedicated Neon demo database. Copy its pooled connection string and its direct connection string.
2. From the project folder, run `npm ci`. Set `DIRECT_DATABASE_URL` to the direct connection in your terminal and run `npm run db:vercel:init`. This creates the schema and installs the demo fixtures. Use a dedicated database and rerun initialization locally before deploying changes that require a schema update.
3. Use `npm run setup` in a fresh local checkout to generate an administrator passphrase hash and session secret. Choose a unique passphrase of at least 12 characters. Use a fresh checkout so existing local secrets are not reused.
4. Import the GitHub repo in Vercel as a Next.js project. Set the deploy branch to the branch containing `vercel.json`. The build command selects the Postgres Prisma schema. Use Node 22 or newer supported by the deployment environment.
5. Configure these Production environment variables before deploying:

   | Variable | Value |
   | --- | --- |
   | `DATABASE_URL` | Neon pooled Postgres connection string |
   | `APP_ORIGIN` | Exact HTTPS URL you will share, without a trailing slash |
   | `COOKIE_SECURE` | `true` |
   | `SESSION_SECRET` | Fresh value generated by local setup |
   | `ADMIN_PASSWORD_HASH` | Fresh hash generated by local setup |
   | `AI_ENABLED` | `false` |

6. Deploy and sign in at the exact origin configured above. Check the Templates and Training tabs. In the administrator bar, **Change passphrase** changes the stored hash and signs out other administrator sessions.

Keep the Postgres connection strings, passphrase, hash, and session secret out of Git and chat. Do not use a default password or reuse credentials from another service. Use separate database and secrets for any Preview environment you enable. The browser demo uses fictional accounts and does not send real emails. The background retention timer is disabled on Vercel; routes that serve retained data or record interactions still run the retention check.

## Refresh an existing hosted demo

From the updated folder, use the direct Neon connection and rerun `npm run db:vercel:init`. The installer adds missing templates and core lessons even if the original demo marker already exists. Existing participants, consent and training progress are preserved. Deploy the updated folder again with `vercel --prod` to publish the new exercise screens and outcome rules.
